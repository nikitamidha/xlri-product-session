The agentic vocabulary

Seven words, the framework that goes with each, and then the whole thing put back inside Jobs to be Done. Twenty minutes.

01 LLM · Agent · Multi-agent 02 Human in the loop 03 Evals · Observability 04 Hybrid workforce 05 The four forces, re-scored
The card0:00 — 1:00

Seven definitions. Write them down.

LLM
A model that turns text into more text — it can advise, and it cannot act.
Agent
An LLM placed in a loop with tools and a goal, deciding for itself what to do next and when it is finished.
Multi-agent system
Several agents with different contexts, tools or roles, coordinated toward a single objective.
Human in the loop
A designed point at which the system must stop and obtain a human decision before proceeding.
Evals
A repeatable set of scored cases that says whether the system does the job — QA for output that is probabilistic.
Observability
The ability to reconstruct what the system did on one run, and why.
Hybrid workforce
An operating model that allocates jobs — not roles — across humans and agents as one pool of capacity.

An LLM produces language. An agent produces consequences. Everything else on this list — coordination, gates, evals, workforce design — exists because of that second word.

§1 · LLM1:00 — 3:00

A function from text to text that generalises to tasks nobody built it for

That last clause is the whole commercial event. Software before 2022 could only do what someone specified in advance.

PropertyWhat it meansThe product consequence
StatelessIt remembers nothing between calls. Everything it "knows" about your situation was put there by someone.Context assembly is the product.
ProbabilisticThe same input yields a distribution, not an output.You cannot test it like software. You design for wrongness.
Text-onlyIt emits tokens. No hands, no clock, no memory, no access.On its own it can only tell. Acting takes scaffolding.

It can advise. It cannot act.

§1 · LLM1:00 — 3:00

Three confusions worth killing now

Not a chatbot

Chat is a user interface that was easy to build around the model. It was the first interface, not the right one.

Not a database

It does not look things up. It produces a plausible continuation. When the plausible continuation is false, that is the mechanism working normally — which is why grounding and citations exist.

Not deterministic software

"It worked when I tried it" is not a test result. It is one sample from a distribution, reported by the person most motivated to like it.

The test

If the only output is words on a screen for a human to read and act on, you have an LLM product, not an agent. Frequently the right answer — and a completely different design problem.

§2 · Agent3:00 — 7:00

An LLM in a loop: given a goal, it chooses an action, observes what happened, and decides what to do next — including when to stop

PartWithout it
GoalThe loop never terminates — nothing defines "done"
ModelYou have a script
ToolsIt can only narrate what it would do
ContextIt re-solves the same problem each step, and forgets what it tried
LoopOne shot, no recovery from a bad step
Stop & escalateIt runs forever, or fails silently

An agent with no way to say "I don't know" will invent its way past the uncertainty. That is what the model underneath does.

§2 · Agent3:00 — 7:00

Who decides the next step — you, at design time, or the model, at run time?

SystemWhichWhy
Nightly script that summarises yesterday's tickets and emails the digestWorkflowYou fixed every step; the model fills one slot
Support bot that retrieves from a knowledge base and answersWorkflowRetrieve-then-answer is your sequence, not its choice
Coding tool that reads the repo, edits, runs tests, sees a failure, edits again, stops when greenAgentIt chose the sequence and the stopping condition
Refund system that decides, pays under ₹5,000, escalates aboveAgent, boundedIt decides and acts — inside a fence you drew
Deep research: plans searches, reads, concludes it needs more, writesAgentThe plan is generated at run time

"Agent" is not a compliment and "workflow" is not an insult. Every step you hand to the model buys flexibility and sells reliability. Most systems that work in production are workflows with one agentic step in the middle.

§2 · Agent3:00 — 7:00

The autonomy ladder

0SuggestionHuman does everything except type the wordsinline autocomplete
1AssistantHuman states the task, then does the work with the answerChatGPT, Perplexity
2WorkflowHuman designed the pipeline; reviews the outputdocument processing
3Agent, attendedHuman approves each action, reviews the resultCursor, Claude Code
4Agent, unattendedHuman sets goal and guardrails, audits afterscheduled research; opens a PR
5Agent systemHuman sets objectives, budget, escalation policymostly still being sold, not shipped

Autonomy is not a maturity level to climb. It is a purchase, and the price is the cost of being wrong. The rung is set by reversibility and blast radius — never by how capable the model has become.

§3 · Multi-agent7:00 — 9:00

Several agents, different contexts and permissions, one objective

Note what is not in that definition: the number of models, or the org chart. Two agents can run on the same model. What separates them is context and permissions.

Reason 1 · Context isolation

A messy sub-task doesn't pollute the main thread. A research subagent reads forty pages and returns eight lines.

Reason 2 · Parallelism

Wall-clock time, when the sub-tasks are genuinely independent.

Reason 3 · Independent judgment

An adversarial check by something not invested in the answer. A generator that grades itself grades generously. Most valuable, least used.

Add an agent only when it needs a different context, a different tool set, or a different incentive from the one you already have. Never for symmetry with the human process.

§3 · Multi-agent7:00 — 9:00

More agents usually means less reliability

Reliability compounds downward

0.9510 ≈ 60%

Ten handoffs at 95% each. Adding agents multiplies error; it does not average it.

Every handoff leaks context

AI's real value was that it removed the fidelity loss at the human handoff — the person holding the context now does the work.

A badly designed multi-agent system reintroduces exactly the problem AI just removed. You rebuilt the org chart, including the parts that don't work.

Cost and latency multiply

And non-determinism makes it very hard to say which agent caused the bad output.

Accountability diffuses

Five agents, and nobody to ask what happened.

§4 · Human in the loop9:00 — 11:00

"A human is involved" is a reassurance, not a design

PostureMechanicThe human's real roleWhat it costs
In the loopThe system cannot proceed without a decisionDecides, on the action pathThroughput — every gate is a queue
On the loopIt proceeds; a human monitors and can abortSupervisesVigilance — attention decays
After the loopIt acts; humans audit a sample laterGovernsExposure — you find out afterwards

The question is never whether there is a human in the loop. It is which posture, at which step, and who.

§4 · Human in the loop9:00 — 11:00

Put the gate at the last reversible moment

Small blast radiusLarge blast radius Reversible

Let it run

Log it. Nothing here needs a human's Tuesday.

On the loop

Visible progress, an abort, an undo.

Irreversible

Confirm

With the evidence attached, not just the intention.

In the loop

And a named accountable human, not "the team".

Not an axis on this grid

Model confidence. A model's stated confidence is another generated token. Gate on consequence, which you control — not on confidence, which you don't.

A gate approved 99% of the time is not a control. It is a ritual — and it transfers liability to a person who was never able to check.

§5 · Evals11:00 — 13:00

A repeatable set of cases, scored against a standard, that says whether the last change made it better or only different

It exists because of one property from §1: you cannot unit-test a distribution. "It worked when I tried it" is one sample, reported by the person most motivated to like it.

Cases

Real inputs with their real context.

Weak → you get very good at situations your users do not have.

Grader

The thing that decides pass, fail, or score.

Weak → the number moves and nobody believes it.

Tracked history

The same suite, run on every change.

Weak → you ship regressions and hear about them from users.

Three ways to gradeRight forWatch out for
ProgrammaticRight tool called, output well-formed, under budget, did it stopOnly reaches what you can express in code
LLM-as-judgeRubric quality — faithfulness, completeness, toneNeeds its own calibration. An ungraded grader is a rumour.
HumanThe hard cases; setting the standard the other two imitateExpensive. Calibrate with it; don't run the suite on it
§5 · Evals11:00 — 13:00

For an agent, you are not grading an answer. You are grading a route.

AxisThe questionWhat only this axis catches
OutcomeDid the world end up in the right state?The refund is correct, the PR is right, the record matches
ProcessWas the route acceptable?It read every customer record to decide, took forty steps, spent twelve dollars, and never escalated the one ambiguous case

Where the cases come from

Production. Every escalation, every reworked output, every complaint is a case with a known right answer. An eval set is the memory of the product's mistakes.

Two traps

Benchmark theatre — public benchmarks measure somebody else's job. Optimising the suite — the eval set quietly becomes the roadmap, so whatever is not in it is not improving.

Grade only outcomes and you are training a system to be lucky. And: you do not ship an agent because it worked — you ship it because it stopped failing where it used to, and you can show the number.

§6 · Observability13:00 — 14:30

Reconstructing what the system did on one particular run — and why it did that

The unit is the trace: the request, the context assembled, every model call, every tool call and what it returned, the decisions, the cost, the final state.

  1. What did it do? — the actual sequence of actions.
  2. Why did it do that? — what was in the context at that step. The answer is almost always here, and this is the part teams log last.
  3. What did it cost? — tokens, money, wall-clock, and calls to systems that bill you.
  4. Where did it go wrong? — which step, not which run.

Without a trace, every bug report is "it did something odd on Tuesday" and every post-mortem is a séance.

§6 · Observability13:00 — 14:30

A trace has three audiences. Teams build one.

AudienceUses it toNeeds to see
The engineerDebugEverything, raw
The userDecide whether to trust it — and eventually whether to stop watchingA legible account of what was done, with any step openable
The organisationAnswer for itWho authorised what, when, under which policy — and retained

The loop — and it is the entire engineering process of an agent product

production trace → a failure is noticed → it becomes an eval case → the fix is verified against the whole suite → shipped → observed again

Observability tells you what happened. Evals tell you whether it is getting better. Observability without evals is archaeology; evals without observability is a score you cannot diagnose.

§7 · Hybrid workforce14:30 — 16:30

A role is a bundle of jobs. Agents don't replace roles — they unbundle them.

"Analyst" is not a unit of work. It is thirty jobs bundled because they happened to need the same person, in the same place, with the same context. Decompose first, then ask.

Automate

An agent does it end to end.

Test: checkable output, bounded blast radius.

Augment

A human does it faster, with an agent.

Test: judgment sits inside the job, not at the end of it.

Abandon

Nobody does it any more.

Test: the job existed only to work around a constraint that has now gone.

A PM's own weekWhere it goesWhy
First draft of the PRDAugmentThe draft is cheap now; the argument still isn't
Chasing status across five teamsAutomateBounded, checkable, and nobody wanted it
The weekly status deckAbandonIt existed because gathering information was expensive. It isn't.
Telling someone their project is cancelledHumanDelegating it is the message
§7 · Hybrid workforce14:30 — 16:30

What stays human, stated precisely

  • Accountability. An agent cannot be answerable. Somebody must be — a legal and social fact, not a capability gap.
  • Standard-setting. What "good" means here is the input to everything the agents do.
  • Undocumented context. The reasons never written down, and the ones nobody would write down.
  • Consent and relationship. Who gets told what, by whom, in what order.
  • Novel judgment under stakes. The case that is genuinely not like the previous cases.
Old unitNew unit
HeadcountCost per completed job
UtilisationAutonomy rate — % completed with no human touch
Cycle timeEscalation rate, and time-to-verify
Defect countRework rate — work returned after acceptance

None of these exist unless something is recording the work. The trace is the only evidence the work happened.

Two traps: the centaur trap — pair every agent with a reviewer and the reviewer becomes the constraint. And verification debt — output grows faster than the capacity to check it.

§8 · Tie-back16:30 — 20:00

LLMs made an advisor abundant. Agents make a doer abundant.

What became free is not intelligence. It is persistence — attention sustained on your behalf, over time, while you are not watching.

The old test, from the deep dive

"What would this user have had to pay a human to do — and why didn't they?"

The agentic extension

"What would they have had to pay a human to keep doing — and for how long?"

The job, in the user's wordsWhy nobody served it
"Tell me if anything in this contract set changes"Somebody would have had to read them all, every month
"Keep these two systems saying the same thing"A person doing reconciliation forever
"Chase this to done, come back only if it's stuck"You cannot hire a fraction of a person for a fortnight
"Watch for this and wake me"Nobody is paid to wait

Every one is a real job with visible demand that everybody had concluded people didn't want. They were reading a blocked force as an absent job.

§8 · Tie-back16:30 — 20:00

The same instrument, pointed at a new class of product

ForceLLM assistantAgent
PUSHI produce more language than I can typeNew and self-inflicted: assistants let me generate more work than I can execute or check
PULLVivid. "It writes the thing." The demo is compellingWeak. "It'll do it while you're not watching" is hard to picture — and a good agent's demo is nothing happening
ANXIETYModerate, in use. Is this answer right?Very high, different in kind: it acted, I wasn't there, I can't reconstruct what it did, and I am accountable
HABITLow. Personal, easily brokenHigh and organisational: approval chains, audit, "who signs off", existing process, existing headcount

Read the equation off the table — push + pull > anxiety + habit

For agents the binding forces are anxiety and habit, and both are organisational rather than individual. The blocker on an agent sale is almost never capability. It is that nobody can say who is accountable when it is wrong, and the existing process has no slot to put it in.

Which is the good news: anxiety and habit are the two forces a product team can actually work on. Traces, dry-run, sandboxes, scoped permissions, spend limits, undo, gates, an eval number you can show a buyer — and fitting the approval chain that already exists instead of replacing it.

§8 · Tie-back16:30 — 20:00

The job never changed. The standard did — twice.

EraWhat the user will accept
Pre-generative AIOutput I can work with
AssistantsOutput I can send unedited
AgenticWork I didn't have to watch

Which rewrites the job story, once work is delegated rather than performed

When [circumstance], I want [the agent] to [motivation], so I can [outcome] — and I will accept it without checking when [condition].

That last clause is the product specification. Ask it of any agent product in the room; most teams have never written the condition down.

What moved is the standard — which is exactly what JTBD says to look at, and exactly what feature-led analysis never sees.

§8 · Tie-back16:30 — 20:00

Seven questions for any agentic product

  1. What job is being delegated, and at what rung? Not "what does it do" — what progress is a person no longer making themselves?
  2. What is the unit of work, and how does the user know it's done? No definition of done, no agent — just a process that never terminates.
  3. Where is the last reversible moment, and what happens there?
  4. What is the evidence surface? If verification costs as much as doing the work, nothing has been delegated.
  5. What does it do when it doesn't know? Show me the escalation path, or the failure mode is confident fabrication.
  6. How would you know it got worse? Which cases, scored how, watched by whom.
  7. Who is accountable when it is wrong — and does the product make that person's job possible? The question that closes agent deals, and the one teams answer last.
§8 · The closing question

Agents put more work in flight than anyone can supervise.

Generative AI created a new push by making us produce far more language than we ever have. Verification was already the bottleneck for code. It is about to be the bottleneck for everything an organisation does.

Where is the product for that side of the exchange?
